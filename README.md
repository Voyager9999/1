# 隔空滑屏（AirSwipe）

用前置摄像头识别挥手：**在镜头前向上挥手 → 自动上滑屏幕 → 刷到下一个视频**。
在抖音、TikTok、小红书、YouTube Shorts、Instagram Reels 等任何 App 里都能用。

工作原理：前台服务以很低的分辨率（约 64×48）读取前置摄像头画面，用帧差法判断画面里有没有一大块东西在快速地上下移动；识别到后，由无障碍服务在当前 App 里模拟一次手指滑动。
App 没有联网权限，画面只在内存里比较，不保存、不上传。

---

## 一、编译安装（二选一）

### 方法 A：Android Studio（最稳）

1. 电脑上安装 Android Studio（免费）。
2. 解压本压缩包，Android Studio → **File → Open**，选择 `AirSwipe` 文件夹，等待 Gradle 同步完成（第一次要下载依赖，几分钟）。
   - 如果提示升级 Android Gradle Plugin，可以忽略，也可以按提示升级。
   - 如果报 JDK 版本错误：Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle JDK，选 17 或 21。
3. 一加 13 打开 USB 调试：设置 → 关于本机 → 版本信息 → 连续点“版本号”7 次；然后在 设置 → 系统与更新 → 开发者选项 里打开“USB 调试”。
4. 数据线连接电脑，点工具栏的绿色 ▶ Run，App 会直接装到手机上。
   （或者 Build → Build APK(s)，把生成的 `app-debug.apk` 传到手机上安装。）

### 方法 B：GitHub 云端编译（不用装 Android Studio）

1. 在 GitHub 新建一个仓库，把解压后的**全部文件**上传（注意要包含隐藏的 `.github` 文件夹）。
2. 打开仓库的 **Actions** 页面，等 “Build APK” 跑完（约 3–5 分钟）。
3. 点进这次运行，在页面底部下载 `AirSwipe-apk`，解压得到 `app-debug.apk`，传到手机安装。

## 二、手机上的设置

1. 打开“隔空滑屏” → 点 **① 授予摄像头和通知权限**。
2. 点 **② 去开启无障碍服务** → 在列表里找到“隔空滑屏” → 打开。
   - **开关是灰色、点不了？** 这是安卓对“非应用商店安装”App 的限制。回到 App 点“打开应用详情” → 右上角 ⋮ → **允许受限制的设置**，再回去开启。（用 Android Studio 直接 Run 安装的一般没有这个限制。）
3. 点 **③ 开始识别**，然后先在本页面挥几下手，看“上次识别”有没有变化。
4. 打开抖音等 App，手掌离屏幕 20–40 厘米，从下往上快速挥过前置摄像头即可。

### 一加 / ColorOS 防止被杀后台

- 设置 → 应用 → 隔空滑屏 → 耗电管理（或电池）→ **允许后台运行 / 不优化**。
- 在最近任务里把“隔空滑屏”的卡片**下拉锁定**。
- 如果发现无障碍服务被系统自动关掉了，重新打开一次即可。

## 三、调整

- **灵敏度**：挥手没反应 → 调高；没挥手也乱翻 → 调低。页面上会实时显示“画面运动量”，挥手时数字应明显超过门槛。
- **只响应向上挥手**（默认开）：挥完手收回来时不会被识别成“上一个”。关掉后，向下挥手 = 回到上一个视频。
- **方向反了**：打开“反转”开关。
- 屏幕关闭时自动关掉摄像头省电，解锁后自动恢复；状态栏的摄像头绿点表示正在识别。
- 通知栏里有“停止”按钮。

## 已知限制

- 这是简单的运动检测，不会专门识别“手”：旁边有人或大物体快速经过镜头，也可能触发一次。
- 光线很暗时画面噪点多，识别会变差。
- 摄像头一直开着会额外耗电，不用时请停止。
- 有些 App 在使用前置摄像头时（例如视频通话），本 App 会暂时无法使用摄像头。

## 代码结构

| 文件 | 作用 |
|---|---|
| `MotionSwipeDetector.kt` | 手势检测算法（纯 Kotlin，可单独测试） |
| `GestureCameraService.kt` | 前台服务，打开前置摄像头并逐帧检测 |
| `SwipeAccessibilityService.kt` | 无障碍服务，模拟滑动手势 |
| `MainActivity.kt` | 设置界面 |
| `AppSettings.kt` | 设置项存储 + 服务与界面之间的通知 |
